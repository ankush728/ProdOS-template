# IdeasSync — Knowledge Context

## Always Load

- `GOALS.md` — Strategic alignment for classification. Understand what the VP of Product cares about so ideas can be evaluated in context.
- `shared/knowledge/truth_pack/TP_04 Product Scope and Module Map.md` — PSTrax module structure. Essential for accurate `module_cluster` classification. This is the authoritative source for what modules exist and what they cover.
- `shared/knowledge/reference/pstrax-module-functionality.md` — Sandbox-validated functional reference (paired companion to TP_04). Captures the actual product surface — URLs, workflows, fields, reports per module. Use to:
  - Verify whether an incoming idea is requesting an existing feature (often the case for `polish` and `depth` class ideas — surface tweaks to known modules)
  - Refine `module_cluster` assignment when title is ambiguous (e.g. "expiration report" maps to which module's expiration report? Check the doc for the existing surfaces)
  - Identify `idea_type` more accurately (`polish` if surface exists and needs UX tuning, `depth` if module exists but feature doesn't, `new-capability` if no related surface)

## Load for Triage

- `shared/knowledge/truth_pack/TP_01A Company Strategy.md` — S1/S2/S3 strategic pillars. Helps prioritize ideas during triage by connecting them to strategic themes.

## Load at Session Start

- `skills/IdeasSync/MEMORY.md` — Classification corrections, kill pass patterns, reporter patterns, known duplicates. Apply learned patterns to improve accuracy.
